# Figma / Notion 工作侧栏（待开发）

状态：设计与技术验证待办，未实现、未部署。

用户已确认：必须复用当前电脑已有的 Figma / Notion 网页登录；不以在独立容器里重新登录作为等价交付。

## 目标

在 HAPI 会话右侧增加可调宽的工作面板，有 Figma、Notion 两个独立标签。
聊天区保留当前会话，切换面板不丢失网页位置。桌面可同时查看聊天和工作网页；手机以全屏工作页切换。
使用当前电脑的登录态；这两个站点及其必要资源请求固定走香港代理。HAPI 页面和公网穿透继续直连；模型请求维持原有代理设置。

## 必须先确认的边界

1. “本地 session”已确认为当前电脑现有浏览器的 Figma / Notion 登录态，具体浏览器／用户配置仍需在实施前识别；不得复制 Cookie 数据库或把登录凭据提交至仓库。
2. 浏览器中的普通 HAPI 网页无法直接取得 Chrome、Edge、ZCode 或其他应用的 Cookie，也无法自行指定某个 iframe 使用哪一个代理。
3. Figma 官方 Embed 是文件／原型嵌入，不等于完整编辑器；跨站 Cookie、文件权限和 Storage Access 授权仍适用。Notion 完整编辑器必须实测响应的 frame-ancestors / X-Frame-Options 和登录跳转，不能承诺可直接 iframe。
4. 不删除第三方防嵌入响应头，不将本机已登录浏览器、远程调试端口或任意 URL 代理暴露到公网。
5. 从手机公网 HAPI 访问“电脑登录态”需要电脑端受鉴权的浏览器渲染／交互桥接，属于独立能力，不是前端加两个 iframe 就能实现。

## 技术方案候选

A. 普通网页：侧栏提供 Figma 官方只读 Embed 和两个站点的“在浏览器打开”入口。复用当前浏览器网页登录，代理由该浏览器／本机分流规则控制。不能保证 Notion 在侧栏内完整编辑。

B. 本机桌面容器：使用独立 WebContentsView 一类网页视图承载完整网站，账号在容器里登录；为工作视图 Session 单独设代理。已有其他浏览器的登录通常无法无缝复用，需要重新登录。

C. 复用现有浏览器扩展：由用户明确授权的扩展／本机桥接与既有标签协作；是否支持嵌入原页面需原型验证。禁止以 iframe 绕过浏览器隔离。

若必须同时满足“原有浏览器登录态 + 真正内嵌 + 手机可远程操作”，先验证 C 或受控远程浏览器方案，再确定实现范围。

## 香港代理设计

- 分离代理配置与账号 Session；不用更改系统全局代理组。
- 桌面容器可给工作 Session 设置专用本机代理端口，代理内只选择已验证香港节点。只有已有混合端口（如 7897）并不能证明出口是香港。
- 普通网页模式由用户实际浏览器所在设备分流；服务器的模型代理不会自动代理手机上的 Figma 请求。
- 域名覆盖按真实网络请求收集，包含 Figma / Notion 主站、静态资源、WebSocket 与认证回调；身份提供商尽量限定在专用工作 Session，避免更改其他应用登录流量。
- 用实际出口 IP 地区和请求路由日志验证；香港节点不可用时明确报错，不静默回退其他地区。

## 验收

- Figma、Notion 可切换，聊天与输入草稿保持；宽度、标签、各自 URL 可在当前浏览器保存。
- URL 仅接受允许的 HTTPS 站点；禁止 javascript/data/file 和任意内网目标。
- 两站分别验证登录、读取、编辑、刷新与重启后的 Session 保留。
- 两站请求和必要子资源有香港路由证据，HAPI 与穿透仍直连。
- 手机交互和本机登录态复用分别验收，未完成前不宣称支持。
